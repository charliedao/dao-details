════════════════════════════════════════════
 DAO DETAILING — NETLIFY ENV SETUP GUIDE
════════════════════════════════════════════

Add these in: Netlify Dashboard → Site Configuration → Environment Variables

─────────────────────────────────────────
 STEP 1 — Get Firebase Service Account
─────────────────────────────────────────
1. Firebase Console → Project Settings → Service accounts
2. Click "Generate new private key" → Download JSON
3. Open the downloaded JSON file

─────────────────────────────────────────
 STEP 2 — Add These 5 Variables
─────────────────────────────────────────

Key:   FIREBASE_PROJECT_ID
Value: dao-detailing

Key:   FIREBASE_CLIENT_EMAIL
Value: (copy "client_email" from the JSON)
       e.g. firebase-adminsdk-xxxxx@dao-detailing.iam.gserviceaccount.com

Key:   FIREBASE_PRIVATE_KEY
Value: (copy the ENTIRE "private_key" from the JSON)
       Keep ALL the \n characters. Keep the BEGIN/END lines.
       e.g. -----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n

Key:   ALLOWED_ORIGIN
Value: https://daodetails.netlify.app

Key:   ADMIN_TOKEN
Value: (make up a long random string — minimum 32 characters)
       e.g. dao2025-xK9mP3qR7nL2vW8tY5uB1cE6aF4jH0
       This is a secret token passed between your browser and functions.
       Never share it. Use any random string you want.

─────────────────────────────────────────
 STEP 3 — Redeploy
─────────────────────────────────────────
After adding all 5 variables, trigger a new deploy.
Netlify will automatically install firebase-admin from package.json.

─────────────────────────────────────────
 SECURITY NOTES
─────────────────────────────────────────
• Keep the downloaded service account JSON private — delete it after setup
• The ADMIN_TOKEN is your second layer of security beyond Firebase Auth
• admin.html only has Firebase Auth config (safe to be public)
• All Firestore reads/writes go through server-side functions only
• No sensitive keys are visible in any browser

─────────────────────────────────────────
 FIRESTORE SECURITY RULES
─────────────────────────────────────────
In Firebase Console → Firestore → Rules, use:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /inquiries/{id} {
      allow create: if true;
      allow read, update, delete: if false;
    }
    match /bookings/{id} {
      allow read, write: if false;
    }
  }
}

NOTE: Since all reads/writes now go through Firebase Admin SDK
(server-side via Netlify Functions), client-side rules can be
fully locked down. The Admin SDK bypasses these rules entirely.
